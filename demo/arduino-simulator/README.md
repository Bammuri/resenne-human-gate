# Button Lab · Arduino 8버튼 AI 컨트롤러

D2–D9에 연결한 버튼 8개로 AI-DLC, Codex·Claude 실행 제어, 사용자 지정 기능을 사용합니다. 버튼 8은 항상 MODE이며, AI가 질문하면 버튼 1–7이 잠시 보기 선택으로 바뀝니다.

## 실행

Python 3.10 이상과 데스크톱 Chrome을 사용합니다. 서버 자체는 Python 표준 라이브러리로 실행됩니다. Codex·Claude 기능에는 각각 설치된 CLI와 본인의 로그인이 필요합니다.

```sh
python3 server.py --cwd /path/to/project
```

기본 주소는 http://127.0.0.1:8765 입니다. 포트 변경은 `--port 8766`을 추가합니다. 웹 시뮬레이션에는 보드가 필요하지 않습니다.

상단의 **Codex**, **Codex YOLO**, **Claude**, **Claude Bypass permissions** 버튼으로 원하는 AI와 실행 모드를 바로 시작합니다. Claude의 일반 모드는 기본 권한 확인을 사용하고, Bypass permissions는 `--dangerously-skip-permissions`로 권한 확인을 생략합니다. 실행 중에는 종료 후 다른 서비스를 선택합니다.

## 버튼과 모드

| 핀 / 버튼 | 모드 1 · AI 제어 (기본) | 모드 2 · AI-DLC | 모드 3 · 커스텀 |
|---|---|---|---|
| D2 / 1 | MODEL · 노브 추론 강도 활성화 | Initialization · 프로젝트 초기화 | 커스텀 1 |
| D3 / 2 | PLAN · 계획 모드 | Ideation · 문제·가치 | 커스텀 2 |
| D4 / 3 | BUILD · 계획 모드 나가기 | Inception · 요구·설계 | 커스텀 3 |
| D5 / 4 | CHECK · AI가 테스트 및 요구사항 검증 | Construction · 구현·검증 | 커스텀 4 |
| D6 / 5 | ACCEPT · 현재 선택 확인 / Enter | Operation · 인수·운영 준비 | 커스텀 5 |
| D7 / 6 | DENIED · 거절하고 다른 대안 요청 | ASK · 자유로운 중간 질문 (MD 저장 없음) | 커스텀 6 |
| D8 / 7 | STOP · 작업 중단 / Esc | RUN NOW · 현재 입력 저장 후 실행 | 커스텀 7 |
| D9 / 8 | MODE → 2 | MODE → 3 | MODE → 1 |

MODE 전환은 실행 중인 작업을 변경하지 않습니다. 화면 위의 MODE 버튼은 물리 버튼 8과 같은 동작입니다. 화면 STOP과 복귀 미리보기는 어느 모드에서도 접근할 수 있습니다. MODE를 길게 누르는 추가 기능은 없습니다.

커스텀 설정에서 7개 버튼의 이름(24자), 대상(웹 AI 또는 기존 Codex 대화), 기능과 프롬프트(8,192자)를 저장합니다. 비어 있는 슬롯은 실행하지 않습니다. 프롬프트는 선택한 AI 대화에 전달됩니다. 모드와 설정은 프로젝트별로 `~/.config/button-lab/<workspace-hash>/controls.json`에 저장됩니다. `BUTTON_LAB_CONFIG_DIR`로 저장 위치를 바꿀 수 있습니다.

## 번호로 답변하기

질문 대기 중에는 기본 모드의 기능보다 답변 선택이 우선합니다. 보기 1은 버튼 1, 보기 2는 버튼 2로 선택하며 없는 번호는 비활성화됩니다. 여러 질문은 하나씩 표시하고, 답변 후 기존 모드로 돌아갑니다. 7개보다 많은 보기는 화면의 이전/다음 또는 노브로 페이지를 넘깁니다. 복수 선택 질문은 버튼으로 선택을 모은 뒤 화면의 선택 완료를 누릅니다. 직접 입력 질문은 답변 입력란을 사용합니다.

화면과 서버 모두 대상 세션·질문 ID를 확인합니다. 질문이 바뀌거나 USB 연결이 끊긴 동안의 입력은 나중에 자동 재전송하지 않습니다. 일반 번호 목록은 질문으로 처리하지 않으며, 일반 텍스트에서는 명확한 선택 요청과 연속된 번호 보기가 있는 경우에만 답변 버튼을 표시합니다.

웹의 네 AI 실행 버튼은 실제 Codex·Claude CLI를 PTY 터미널에서 실행합니다. CLI의 원래 화면, 입력, 색상, 단축키를 그대로 사용하며, AI 요청과 승인·질문 응답은 터미널 화면에서 직접 입력합니다. 별도의 AI 요청 입력란은 표시하지 않습니다. 모드 1의 STOP은 Esc를 전달하고 위쪽 종료 버튼은 세션을 종료합니다. 커스텀 프롬프트는 터미널 입력으로 전달합니다. 현재 CLI 화면에서 번호가 연속된 선택 요청을 감지하면 버튼 1–7이 해당 번호로 바뀝니다. 텍스트 질문은 번호를 입력하고, 커서가 있는 CLI 선택 메뉴는 선택 행으로 이동해 Enter를 전달합니다. 화면이 바뀌었거나 이미 답변한 요청에는 다시 입력하지 않습니다. 일반 설명 목록과 코드 예시는 선택지로 취급하지 않습니다. 인식되지 않는 CLI 메뉴는 터미널에서 직접 입력하세요.

`--thread SESSION_ID`로 지정한 기존 Codex 대화에는 메시지를 전송합니다. 이 대상의 ACCEPT/DENIED는 `yes/no` 대화 메시지이며 외부 승인창을 조작하지 않습니다. 외부에서 실행한 세션의 STOP은 해당 창에서 사용하세요. 새 웹 AI 세션은 기존 대화를 자동으로 가져오지 않습니다.

터미널에서 한국어 입력과 여러 줄 붙여넣기를 사용할 수 있습니다. 노브는 AI-DLC에서 자율성을 조절하고, 모드 1에서는 **MODEL 버튼을 선택했을 때만** 노브로 실행 중인 AI의 추론 강도(low/medium/high/xhigh)를 변경합니다. MODEL을 다시 누르거나 화면 노브를 누르면 CLI 모델 목록을 엽니다. 다른 기능 버튼을 선택하거나 모드를 바꾸면 추론 강도 조절은 해제됩니다. Codex에는 Shift+위/아래 단축키, Claude에는 `/effort 수준`을 전달합니다. 미실행 상태에서는 다음 실행의 강도를 설정합니다. 모델별 지원 수준과 적용 결과는 CLI 표시를 기준으로 합니다. 질문이 표시된 동안 노브는 보기 페이지를 넘깁니다.

## AI-DLC 사용

모드 2는 [AI-DLC의 다섯 phase](https://awslabs.github.io/aidlc-workflows/reference/04-stages/inception/)를 프로젝트 작업 화면에 맞춰 구성합니다. 1–5번은 해당 입력 화면을 열고, **6 ASK**는 AI-DLC와 별개의 중간 질문 창을 열고, **7 RUN NOW**는 입력을 저장한 뒤 노브의 자율성 설정으로 추가 승인 없이 바로 실행합니다. 중단은 화면의 AI 즉시 중단 버튼을 사용합니다. 모달은 같은 큰 크기를 유지하고 내용만 내부에서 스크롤됩니다.

| 단계 | 입력 | 저장 문서 |
|---|---|---|
| Initialization | 프로젝트 유형, 코드·문서, 개발 환경, 작업 규칙 | `aidlc-docs/01-initialization.md` |
| Ideation | 문제·가치, 사용자, 범위, 성공 기준 | `aidlc-docs/02-ideation.md` |
| Inception | 사용자 스토리·인수 조건, 질문·답변, 설계·작업 단위, 위험·검증 전략 | `aidlc-docs/03-inception.md` |
| Construction | 구현 단위, 변경 범위, 검사 명령, 경계·실물 검증 | `aidlc-docs/04-construction.md` |
| Operation | 인수 판단, 배포 전 조건, 모니터링·장애 대응, 복구·인수인계 | `aidlc-docs/05-operation.md` |

입력 후 해당 단계의 **MD 저장**을 누릅니다. 단계 사이를 이동해도 미저장 입력은 유지하며, ASK는 사용자가 직접 입력한 질문에 답하며, 단계 입력을 가져오거나 질문·답변을 MD에 저장하지 않습니다. AI-DLC 실행 중에도 독립적으로 사용할 수 있습니다. ASK 내용은 서버 메모리에서만 유지합니다. RUN NOW는 수정한 입력을 먼저 저장하고 실행합니다. AI 결과도 같은 단계의 MD에 저장됩니다. 상위 단계의 입력을 바꾸면 하위 단계 결과와 계획 승인을 무효화하되 입력 초안은 유지합니다. 재시작하면 저장한 입력과 결과를 복원합니다. 실행 중이던 프로세스·안전지점·실행 승인은 재시작 시 복원하지 않으며, 구현을 다시 시작할 때 현재 코드 기준으로 설계를 갱신해야 합니다.

모드 2의 A0 노브는 다음 여섯 단계로 자동화 수준을 조절합니다. 모드 1의 Low/Medium/High/XHigh와 독립적입니다.

| 값 | 수준 | 동작 |
|---|---|---|
| 0 | 수동 | 선택 단계까지 실행 (필요한 선행 조사·설계 자동 준비) |
| 1 | 가이드 | 선택한 단계 완료 후 다음 단계 안내 |
| 2 | 단계 전환 | 완료 후 다음 단계 입력 화면으로 이동, 실행은 7 RUN NOW |
| 3 | 자동 검증 | 단계들을 연속 실행하고 추가 회귀·경계 조건 검사 |
| 4 | 자동 구현 | AI가 결정·계획 승인 후 구현과 검증까지 진행 |
| 5 | Full Auto | AI가 결정·계획 승인 후 Operation 문서까지 연속 진행 |

자동 진행에는 Ideation의 목표를 먼저 저장해야 합니다. Full Auto는 저장된 목표와 범위 안에서 일반적인 결정을 스스로 처리합니다. 실제 인증 실패·장치 미연결·검증 실패 같은 실행 불가 사유는 기록하고 중단합니다. Operation은 운영 준비와 점검 문서를 작성하며 실제 배포나 외부 인프라 변경은 실행하지 않습니다. 실행 중 자동화 수준은 고정하며, 변경하려면 화면 STOP 후 노브를 조절합니다.

Construction 직전 코드의 안전지점을 저장합니다. 복귀는 변경 내용을 미리 보고 직접 실행하며, 복귀 전 현재 파일도 별도 백업합니다. `aidlc-docs`, `.git`, 의존성·캐시·빌드 결과는 코드 복귀 대상에서 제외합니다. 파일당 32MiB/전체 128MiB/10,000개 한도이며 심볼릭 링크는 지원하지 않습니다. 워크플로는 별도 Codex 작업이므로 웹 AI 세션을 종료한 뒤 실행합니다.

## UNO R4 WiFi 배선과 업로드

현재 펌웨어는 UNO R4 WiFi 전용입니다. 이전 R3/KY-040 스케치는 `firmware/legacy-encoder/legacy-encoder.ino`에 보관했습니다.

| UNO 핀 | 연결 |
|---|---|
| D0 / RX | DFPlayer Pro TX (`Serial1`, 115200 baud) |
| D1 / TX | DFPlayer Pro RX |
| D2–D9 | 버튼 1–8 각각 한 접점, 반대 접점은 GND |
| A0 | 10kΩ 선형 가변저항 가운데 와이퍼 |
| 5V / GND | 가변저항 바깥쪽 두 단자 |
| A4 / SDA, A5 / SCL | OLED SDA, SCK/SCL (`Wire`) |
| USB-C | PC 통신 (`Serial`), 업로드, UNO 전원 |

버튼은 각각 INPUT_PULLUP과 30ms 디바운싱을 적용하며, 8개 모두 독립 입력 이벤트를 보냅니다. 버튼 기능은 PC에서 지정합니다. 현재 시뮬레이터는 기존처럼 8번을 MODE로 사용하며 음원 재생에 고정하지 않습니다. D10은 WS2812B LED 8개에 사용하며, D11–D13과 A1–A3은 사용하지 않습니다.

A0는 풀업 없는 10비트 ADC입니다. 평균 필터와 변화 임계값으로 잡음을 줄이고, 최초 위치는 동작을 발생시키지 않습니다. **3핀 가변저항에는 누름 기능이 없습니다.** MODEL 버튼을 한 번 누르면 추론 강도를 조절하고, 다시 누르면 CLI 모델 목록을 엽니다. 다른 기능에서는 위치 변화가 스크롤·기록 탐색 등으로 전달됩니다. 회전 범위 끝에서는 반대로 돌려야 하며, 엔코더처럼 무한 회전하지 않습니다.

OLED는 SSD1306 128×64를 가정하고 0x3C, 0x3D를 순서대로 확인합니다. 주소 응답만으로 컨트롤러·해상도·전압 호환성을 확정하지 않습니다. 모듈 사양에 맞는 전원과 I2C 신호 레벨을 사용하세요. 화면이 없어도 USB 입력과 Wi-Fi는 동작합니다.

DFPlayer Pro VIN은 안정적인 외부 5V, GND는 외부 전원 및 UNO와 공통 연결합니다. 스피커는 L+·L− 사이에 연결합니다. L−는 GND에 연결하지 않습니다. 사용하지 않는 오른쪽 채널·DAC·KEY·PLAY 단자는 연결하지 않습니다.

1. `firmware/simulator_r4/wifi_credentials.h`에서 AP 이름과 Wi-Fi 비밀번호를 설정합니다. 현재 AP 이름은 `DM`이며 API 토큰은 없습니다. 웹 다운로드 설정 예시에는 실제 비밀번호를 넣지 않습니다.
2. Arduino IDE에서 `firmware/simulator_r4/simulator_r4.ino`를 열고 **UNO R4 WiFi**와 USB 포트를 선택합니다. WiFiS3·EEPROM은 보드 패키지에 포함됩니다. Adafruit SSD1306, GFX, BusIO, NeoPixel이 필요합니다.
3. USB 연결/시리얼 모니터를 해제하고 업로드합니다. 첫 실행은 설정용 AP입니다. 실제 IP는 OLED 또는 USB의 `wifi:info` 응답을 확인합니다.

## Wi-Fi 연결

- 초기 AP: `BOARD_AP_SSID` (현재 이름 `DM`), 비밀번호는 로컬 `wifi_credentials.h`의 `BOARD_AP_PASSWORD`입니다. PC/휴대폰을 이 AP에 연결하면 보드 설정 페이지(기본 `http://192.168.4.1/`)를 열 수 있습니다.
- 설정 페이지에 공유기 SSID·비밀번호만 입력하면 EEPROM에 저장하고 공유기로 연결합니다. 연결 실패 시 AP로 돌아옵니다. 공유기는 UNO R4가 지원하는 2.4GHz Wi-Fi를 사용합니다.
- 같은 공유기에 연결된 PC에서 시뮬레이터의 **실물 → Wi-Fi**를 선택하고 OLED의 IP만 입력합니다. 공유기 설정 없이 보드 AP에 직접 연결해서도 제어할 수 있습니다.
- Wi-Fi 버튼 이벤트는 새 연결 시점 이후만 받습니다. 보드 재시작·이벤트 누락·전송 불확실성 발생 시 다시 연결해야 하며, 명령을 자동 재전송하지 않습니다. USB와 Wi-Fi 중 하나를 선택해 사용합니다.
- A0 입력은 MODEL을 선택했을 때만 Low/Medium/High/XHigh로 적용됩니다. 선택된 기능이 바뀌면 현재 위치를 다시 기준점으로 잡습니다.

보드 HTTP API는 아래와 같습니다. `/status`, `/events`, `/command`에는 토큰 헤더가 필요하지 않습니다. 신뢰하는 로컬 네트워크에서 사용하세요.

| API | 동작 |
|---|---|
| `GET /` | 공유기 설정 페이지 |
| `GET /status` | 보드·IP·A0·OLED·MP3 최근 응답 |
| `GET /events?after=N` | 번호 N 이후 버튼·A0·모듈 이벤트 |
| `POST /command` | 본문에 한 줄 명령 (`text/plain`) |
| `POST /wifi` | 설정 폼: `key`, `ssid`, `password` |

USB는 115200 baud, 명령 끝에 개행을 사용합니다. Wi-Fi `/command` 본문에는 개행을 붙이지 않습니다. 두 경로는 같은 명령 처리기를 사용합니다.

| 명령 / 이벤트 | 의미 |
|---|---|
| `BUTTON_LAB_HELLO` | `BUTTON_LAB_READY:3:slots=8:knob=analog` 응답 |
| `key:1` … `key:8` | 해당 번호 왕복 이벤트 |
| `BUTTON_LAB_KEY:1` … `:8` | 실물 버튼 눌림 |
| `BUTTON_LAB_POT:0` … `:1023` | 실제 A0 위치 변화 |
| `mode:toggle` | 기존 시뮬레이터 MODE 왕복 |
| `display:agent:model:2:ready` | OLED 기능·강도·상태 표시 |
| `wifi:info` | AP/공유기 모드와 IP 조회 |
| `audio:toggle` | 재생 / 일시정지 전환 |
| `audio:next`, `audio:previous` | 다음 / 이전 음원 |
| `audio:play:1` | 파일 번호로 재생 (1–9999) |
| `audio:volume:10` | 음량 설정 (0–30) |
| `audio:status` | 현재 파일 이름 조회 |

DFPlayer 명령은 [DFRobot 공식 AT 프로토콜](https://wiki.dfrobot.com/dfr0768/docs/20422)에 따라 `Serial1`으로 CRLF와 함께 전달합니다. `BUTTON_LAB_AUDIO_SENT`는 UART에 명령을 보냈다는 뜻이고, 실제 모듈 응답은 `BUTTON_LAB_AUDIO`로 따로 받습니다. 전원 인가 시 모듈 자체가 재생을 시작할 수 있으며 펌웨어가 버튼이나 A0를 음원에 자동 연결하지는 않습니다. 실물 연결 영역의 음원 제어 또는 API로 명시적으로 명령합니다.

## 버튼별 노브 기능

모드 1의 DENIED는 “현재 제안은 거절합니다. 같은 방법을 반복하지 말고 다른 대안을 제안해 주세요. 새 대안은 바로 실행하지 말고 제 승인을 기다려 주세요.”를 터미널에 전송합니다. 번호 질문이 떠 있을 때는 6번 보기 선택이 우선입니다.

| 선택한 버튼 | 노브 위치 변화 | 화면 노브 누름 (A0에는 없음) |
|---|---|---|
| 미선택 | 출력 스크롤 | 최신 출력 |
| PLAN | 계획 페이지 탐색 | 맨 위 |
| BUILD | 입력 기록 위·아래 | 터미널 포커스 |
| ACCEPT | 메뉴 항목 위·아래 | 현재 선택 확인 |
| DENIED | 입력 커서 좌·우 | 취소 |
| MODEL | Low / Medium / High / XHigh | CLI 모델 목록 |
| CHECK | 검증 결과 페이지 탐색 | 최신 출력 |
| STOP | 중단 전 로그 스크롤 | 최신 출력 |

번호 질문이 표시되면 노브는 보기 페이지 이동이 우선이며, 답변은 번호 버튼으로 보냅니다. 화면에서 선택된 기능 버튼을 강조하고 OLED에 현재 노브 기능을 표시합니다. 모드 2의 노브는 AI-DLC 자율성, 모드 3의 노브는 출력 스크롤입니다.

보관된 KY-040 펌웨어는 노브 입력을 `BUTTON_LAB_KNOB:left`, `right`, `press`로 전송합니다. 현재 A0 펌웨어는 위치 값만 전송합니다. 가변저항에는 회전 끝점이 있고 누름 기능은 없습니다. 모델 목록은 MODEL 버튼을 다시 누르면 열립니다. 화면→Arduino 왕복은 `knob:left/right/press`와 `BUTTON_LAB_SIMULATED_KNOB:...`를 사용합니다. 구형 펌웨어의 effort 이벤트는 MODEL 선택 또는 AI-DLC 모드에서만 적용됩니다. 실물 보드에도 새 스케치를 업로드해야 A0 입력과 Wi-Fi 기능을 사용할 수 있습니다.

OLED는 중앙에 현재 기능(MODEL / PLAN / BUILD / CHECK 등)을 표시하고, 아래에는 해당 노브 기능이나 자율성 수준을 표시합니다. 작업 중에는 OLED 전체가 전용 화면으로 전환되어 큰 RUNNING, 움직이는 7개 블록과 경과 시간(분:초)을 표시합니다. 블록은 진행률이 아닌 작업 중 표시이며 250ms마다 이동합니다. 웹과 실물 보드의 모든 모드에 적용되며, 번호 선택 대기는 답변 안내, 작업 종료는 기존 기능 화면으로 즉시 돌아갑니다. 경과 시간은 각 화면에서 실행 상태를 감지한 시점부터 계산하며 답변 후 다시 실행하면 새로 시작합니다. 네이티브 CLI 작업 여부는 현재 터미널 하단의 `esc to interrupt` 등 작업 표시로 감지하므로 터미널이 열려 있다는 이유만으로 실행 중으로 표시하지 않습니다. CLI 표시 형식이 바뀌면 감지 규칙을 갱신해야 합니다. 보드 IP는 최초 연결 안내에서 표시하며 연결 이후에는 기능 화면을 사용합니다. IP는 `wifi:info` 또는 `/status`로도 확인할 수 있습니다.

모드 2의 사람 입력: 각 단계에 목적에 맞는 입력과 **사람의 지시·판단·예외 처리** 항목이 있습니다. Ideation은 목표·범위 Go/No-Go, Inception은 기존 계획 승인, Construction은 구현 결과 승인, Operation은 Production 판단·운영 정책을 기록합니다. 수동~승인형 자동(0~3)은 Ideation 승인 없이 설계·구현으로 넘어가지 않으며, 구현 결과 승인 전에는 Operation으로 넘어가지 않습니다. 4~5는 위임한 범위에서 자동 판단하지만 명시한 보류·거절을 우회하지 않습니다. 실제 배포는 이 앱의 실행 범위에 포함되지 않습니다.

입력·지시·진행 판단은 `aidlc-docs/01-initialization.md`부터 `05-operation.md`까지 저장되며 실행 규칙으로 AI에 전달됩니다. 판단만 바꾸면 검토 중인 결과를 유지하고, 작업 기준을 바꾸면 후속 결과와 승인을 무효화합니다. 실행 중에도 다른 단계의 초안을 작성할 수 있습니다. **실행 중단 후 MD 저장**은 현재 작업을 중단하고 해당 입력을 저장하며, 새 지시의 실행은 RUN NOW로 시작합니다. ASK의 질문·답변은 계속 자동 저장하지 않습니다. 채택한 답변은 사람의 지시 항목에 작성해 명시적으로 저장하세요.

단계별 입력은 큰 작성창 하나로 통합했습니다. 기존 개별 항목의 내용은 제목과 함께 한 창에 표시되며 저장하면 통합 입력으로 전환됩니다. 각 단계에 다른 작성 예시를 항상 표시하고, 빈 창에서만 **예시로 시작**을 사용할 수 있습니다. 승인·보류는 선택 버튼으로 유지하며 예시를 넣는 것만으로 자동 승인하지 않습니다.

단계 입력 모달은 입력창 하나와 저장 버튼만 표시합니다. 단계는 보드의 1~5번 버튼에서 선택하고, 저장하면 모달을 닫습니다. 저장 없이 닫을 때는 Esc 또는 모달 바깥을 누릅니다. 단계별 초안은 화면 안에서 유지합니다.

입력 모달은 닫기(×), Esc, 바깥 클릭으로 닫습니다. 입력을 400ms 멈추면 자동으로 MD에 저장하고, 닫을 때도 마지막 변경을 저장합니다. 저장 요청 중에 계속 입력한 내용은 이어서 저장합니다. AI 실행 중인 경우에는 작업을 임의로 중단하지 않고 완료 후 저장하며 버튼에 대기 상태를 표시합니다. 기본 샘플은 간단한 할 일 목록 웹앱이며, 열어서 보기만 한 샘플은 자동 저장하지 않습니다.
