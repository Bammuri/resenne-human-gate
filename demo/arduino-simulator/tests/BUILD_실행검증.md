# BUILD 실제 실행 검증

2026-09-09, macOS의 실제 Google Chrome(헤드리스)과 Claude Code v2.1.266으로 확인했다. 시뮬레이터의 화면 버튼을 Playwright로 클릭했으며 AI 응답이나 파일 생성을 모의 처리하지 않았다. 기존 사용자 세션 대신 별도 서버(8876 포트)와 임시 작업 폴더를 사용했다.

## 확인 결과

| 확인 항목 | 실제 결과 |
|---|---|
| PLAN 진입 후 바탕화면 프롬프트 입력 | 계획 모드 진입, 조사와 계획 응답 완료. 구현 전 작업 폴더에 제품 파일 없음 |
| BUILD 클릭 | 모드 전환 입력 뒤 구현 요청이 한 번 전송됨. Claude가 실제 계산기 파일 6개 생성 |
| CHECK 클릭 | 현재 파일 검증 요청 전달, 계산 테스트 6개 통과. 같은 테스트를 별도로 실행해서 결과 재확인 |
| CHECK 이후 질문 | 번호 메뉴 없이 “이 결과를 승인할까요, 거절할까요?” 출력 |
| 수정 후 PLAN → BUILD 재실행 | 계획 단계에는 없던 `build-proof.txt`가 BUILD 후 생성되고 `BUILD_OK` 한 줄 확인 |

| 작성 중인 입력이 있을 때 BUILD 클릭 | 기존 입력 유지, 구현 요청 추가 전송 없음, 입력을 먼저 보내거나 지우라는 안내 표시 |
| 브라우저 스크립트 오류 | 없음 |
| 실행 중인 사용자 서버의 반영 상태 | 8765 포트가 제공하는 `web-terminal.js`, `controls.js`가 수정된 로컬 파일과 바이트 단위로 일치 |

## 실제 실행에서 발견하고 수정한 문제

Claude가 PLAN을 해제하면 `auto mode on`을 표시하지만 기존 감지 코드는 이를 구현 모드로 인식하지 못했다. 화면 갱신 시 앱 내부 상태가 PLAN으로 남아 다음 BUILD에서 불필요한 모드 전환이 발생할 수 있었다.

`controls.js`의 모드 감지에 실제로 관찰한 `auto mode on`과 `manual mode on`을 추가했다. 수정된 페이지로 다시 접속해 PLAN → BUILD 및 BUILD 상태의 재요청을 실제 실행하고 확인했다. 해당 화면 문자열에 대한 회귀 검사도 추가했다.

기존 커스텀 모드 테스트 3건은 음원 고정 키인 1–4번을 일반 AI 키로 기대하고 있었다. 제품 동작을 바꾸지 않고, AI 기능이 가능한 5–6번과 음원 고정 키를 각각 검사하도록 기대값을 갱신했다.

이 기록은 실제 Chrome → 시뮬레이터 → Claude CLI의 PLAN/BUILD/CHECK 연결을 검증한다. 실물 보드의 물리 버튼, Codex 실연결, 최종 ACCEPT/DENIED 버튼 응답까지의 전체 시연, 생성된 계산기의 브라우저 UI 품질은 이번 검증 범위에 포함하지 않았다. ACCEPT는 기존처럼 Enter를 전달한다.
